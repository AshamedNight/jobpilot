# jobpilot · 求职助手

自动化求职编排层：**筛岗位 → 海投打招呼 → 跟进 HR 回复 → 促成并接受微信交换 → 把微信号交给你**。

> **当前状态：Phase 1「e2e 批」已完成。**
> `/api/run/sweep` 与 `/api/run/followup` 已接成 fake 全链路：打分 → 额度截断 → 打招呼 → 消息入库 → 交换 → 拿到微信号。
> `ADAPTER=fake`，**全程离线**：不发任何网络请求、不登录、不接真实 BOSS、不调真实 LLM。
> 所有数据来自内置剧本（`app/adapters/fake.py`）。
>
> **Phase 2「P2-C · LLM 生成策略开关」已完成**：`llm.mode` 五档（`off / cache / batch / hybrid / live`），
> 默认 `off` = 纯模板、零 token。任何模式下出错/超时/超预算/无 key 都退回模板，流水线不停，
> 且**回落一律留痕**（`llm_calls.model='template:fallback'` + `/api/status.llm.last_fallback_reason`）。
> 本批**未改 `core/` 任何一行**：换策略 = 换注入给 `compose_opener()` 的对象。

## 5. 数据模型

六张表：`jobs` / `conversations` / `messages` / `actions` / `llm_calls` / `runs`。
SQLite 开 **WAL**。两个唯一约束：

- `actions.idempotency_key` **UNIQUE** —— 防重发。**宁可漏发，不可重发。**
  键格式：`greet:{job_id}`（不是 uid，uid 打完招呼才有）/ `reply:{uid}:{platform_mid}` / `exchange:{uid}`
- `messages(uid, platform_mid)` **UNIQUE** —— 同一批消息读两次不重复入库

`jobs.security_id` 是 `greet` 必需参数，属敏感字段：**不进日志、不进导出、不进 API 响应**。

## 单账号连接 BOSS（本机，仅登录态）

只做一件事：点「连接 BOSS」→ 打开/复用专用浏览器 → 你自己扫码 → 服务把登录态同步到
**新号专用凭据目录** → 页面显示结果。不发送、不搜索、不评分、不清风险锁、不自动重试。
**连接成功 ≠ 发送授权**：业务发送仍按既有闸门与日额度执行。

### 三个绝对路径（都由环境变量给，代码里不写死）

| 环境变量 | 含义 | 说明 |
|---|---|---|
| `JOBPILOT_BOSS_CRED_DIR` | 新号**凭据根**（CLI 的 `--data-dir`） | 真机形如 `<你的用户目录>\.boss-agent-jobpilot-new`；**必须显式给**。真实凭据在 `<根>\auth\` 下（`session.enc` / `salt` / `refresh.lock`），**不是**根目录 |
| `JOBPILOT_BOSS_BUDGET_DIR` | **共享**请求预算 / 风险锁目录 | 必须与 `config.json` 的 `request_budget_dir` 一致，否则拒绝 |
| `JOBPILOT_CDP_URL` | 专用 Chrome 的 CDP 地址 | 默认 `http://127.0.0.1:9222` |
| `JOBPILOT_CHROME_EXE` | 专用 Chrome 可执行文件 | **显式绝对路径**；缺了不崩，点连接时安全拒绝 |
| `JOBPILOT_CHROME_PROFILE_DIR` | 专用 profile 目录 | **显式绝对路径**，不得是日常 Chrome 默认用户目录 |

可选：`JOBPILOT_CONNECT_TIMEOUT_S`（登录超时，默认 120 秒）。

连接状态与账号绑定摘要写在**数据库所在目录**的 `connect/` 下
（`account_binding.json` / `secret.key` / `session.enc.bak`），**不写进凭据目录、不进仓库、
不进交付包**。绑定摘要 = `HMAC-SHA256(本机密钥, 稳定账号字段)`，只用于比对，**不回显**。

### 接口

- `GET /api/connect/status` → `state`（`disconnected` / `connecting` / `connected` /
  `failed` / `needs_user_action` / `timeout`）、`reason`、`message`、`updated_at`、
  `task_active`、`cancel_supported`（恒 `false`）、`binding`、`session_preserved`。
  **不含** token / cookie / 凭据路径 / 账号指纹 / 原始上游信封。
- `POST /api/connect/start`（body 可选 `{"confirm_bind": true}`）→ 200 或
  409（已有连接任务 / 业务运行中）、503（风险锁存在）、403（非本机来源）。
- **没有取消端点**：上游登录是阻塞调用、无法中断，所以不提供"假取消"。
  连接中请等待完成，或按既有流程停止服务。

### 规则（写死在实现里，不是文档约定）

1. **单任务互斥**：`connecting` 期间重复点击只会拿到 409，不会开第二个浏览器/第二个登录任务；
   任务带租约，**超时只改展示状态、不释放占用**——旧线程没退出前，新的连接与业务发送继续被拒
   （那一刻上游可能正在写凭据）。状态是内存态，但"任务已开始 / 恢复待办"落盘在 `connect/` 下，
   **重启不会消除不确定性**：见到记录就阻断，等人工核对原凭据与原账号。
2. **"登录完成"四道判据**：登录信封 ok → 凭据非空落盘 → 本地登录态可确认 → 账号身份核验通过。
   "浏览器打开了" / "session 文件存在"都不算。
3. **旧凭据必须保住**：调用登录前**先落任务开始记录**，再备份 `<cred>\auth\session.enc` **与**`salt`，
   失败 / 超时 / 半写 / 同步不完整一律按字节回滚并**读回核验**；
   状态里 `session_preserved: true` 表示旧凭据已字节级还原，`null` 表示连接前本就没有（新写的必须删掉）。
   恢复失败 = 落恢复待办并持续阻断，不谎报"已保留"。
4. **账号无法确认就停**：拿不到身份 → `needs_user_action/account_identity_unverified`；
   与既有绑定不一致 → `needs_user_action/account_mismatch`（不覆盖旧凭据、不自动修复）。
   首次连接必须显式 `confirm_bind: true`，**不自动绑定**。
5. **不自动清锁**：代码里没有 `clean` / `--risk-lock` / `--force` / `--ignore-risk-lock`；
   发现风险锁直接 503 并提示人工走既有恢复流程。
6. **只本机**：`Host` 必须回环，`Origin` 若存在也必须回环，`sec-fetch-site: cross-site` 直接 403；
   不加 CORS、不绑 `0.0.0.0`、不新增远程管理入口。
